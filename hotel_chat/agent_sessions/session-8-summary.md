## 1. Premise

Session 7 shipped the messaging write path and desktop layout via parallel worktree agents. ## 2. Key decisions and forks in the road

| #   | Topic                          | Decision                                                                                                                                                                                                                                                                                                    |
| --- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | DM pair, DB-enforced           | `dm_key` (free-form text, format enforced by convention in three writers) replaced by `dm_member_a`/`dm_member_b` uuid columns. First-principles ruling: the string's only real job is giving the DM pair a *single-row representation* so a unique index can enforce one-DM-per-pair — the pair otherwise spans two `conversation_members` rows, out of any constraint's reach. CHECK pair-iff-DM, CHECK `a < b` (canonical order, bans self-DMs), partial unique `(company_id, a, b)`. |
| 2   | Membership via composite FKs   | `(id, dm_member_x) → conversation_members (conversation_id, member_id)`, `DEFERRABLE INITIALLY DEFERRED` (memberships insert after the conversation row; checked at commit). Each id must be a member *of that conversation*; no direct FK to `members` — validity is transitive. Rejected: a generated `dm_key` column (PG17 excludes stored generated columns from logical replication, so it would never sync through Electric) and trigger-enforced pair↔membership equality (deferred-trigger machinery guarding a divergence only our own write path could produce). Caveat: the Ecto SQL sandbox never commits, so ExUnit can't exercise the deferred FKs — verified live instead. Follow-up found on a clean checkout: each `insert_all` in seeds commits its own implicit transaction, so fresh-DB seeding failed the commit-time FK check before membership rows existed — conversations + memberships now seed in one transaction, mirroring the write path. |
| 3   | Duplicate DM → return existing | On a pair conflict the server returns the existing conversation (200, `txid: null`) instead of 422; the client dedupes on the synced id columns and follows the server's canonical id if its local dedupe raced.                                                                                              |
| 4   | Group-create affordance        | "Create group chat" looked broken: the button was `disabled` pending a group name, but `.btn` had no disabled styling, so clicks were silently swallowed. Fix the affordance, not the rule: real not-actionable styling (dimmed, `not-allowed`) for `disabled` *and* `aria-disabled`; while only the name is missing the button uses `aria-disabled` — still receiving the click — and responds with a red border (new `--error` brand token) + focus on the Group name input. Truly empty selections keep plain `disabled`. Playwright gotcha: its actionability check refuses `aria-disabled` elements — e2e needs `click({ force: true })`. |
| 5   | Dead sidebar chrome            | The desktop sidebar's static Search field and pencil button removed (neither did anything); mobile/People/New-chat search fields deliberately left for a later pass.                                                                                                                                          |
| 6   | `?as=` session switch          | MockSession pinned every browser to Priya, making the headline demo — two members messaging live — impossible. A `?as=<seed-slug>` param (default `priya`), persisted in sessionStorage (per-tab by design), now picks the acting member and rides on every sync/API request; the proxy consumes it for $me/$company scoping and never forwards it to Electric. MockSession resolves the slug to the seeded member row; unknown/inactive members are a 404 and the tab resets itself. All TEMPORARY(auth). |
| 7   | `/api/session` bootstrap       | The frontend stops hardcoding Priya's profile constants: new `GET /api/session` returns member id/name/phone/company/announcement permission, fetched before first render. Deliberately the shape of the future auth seam — real login replaces how the endpoint identifies the member, not the bootstrap contract. `can_post_announcements` now defaults to the member's real column, query-param flag kept as explicit override. |
| 8   | Scroll-to-bottom               | A `ScrollToLatest` anchor (keyed by conversation id) jumps to the bottom when messages first render and smooth-follows new ones only while already near the bottom — never yanking a reader out of history. Mobile gotcha: `.phone` is min-height-sized so the *document* scrolls and the composer is sticky — the scroll target must be the nearest ancestor that *actually* overflows, falling back to `document.scrollingElement`. Late content growth (webfont metrics, reaction chips syncing in) left the initial jump ~28px short; a ResizeObserver re-pins under the same near-bottom guard. |
| 9   | Mockup landing page retired    | `/` served the session-2 screen index whose slug-based demo URLs (`/chat/wedding-ops` …) stopped resolving when real seeded ids replaced the fixtures. The root now redirects to `/chats`.                                                                                                                    |
| 10  | Mark-read render-loop bug      | Scrolling an unread group chat to the bottom crashed the page ("Maximum update depth exceeded") while firing 54 `POST /read`s in 8s. Root cause was a chain: the seed transcripts hardcode day-0 wall-clock times up to ~noon *as UTC*, so a morning reseed dated 14 messages hours into the future; the read cursor was set to the *client clock*, which could never pass them; and the sentinel effect re-fired on every optimistic membership update with `unread` still positive — a synchronous render loop. (Every earlier seeding had happened in the evening, hiding it.) Fixed at three independent layers, any one of which kills the loop: the seed timeline anchors one day back whenever its day-0 ceiling is still ahead of `utc_now` (offsets shift together, ordering preserved; existing future rows shifted in place); the client cursor is now the newest rendered message's own `inserted_at` — unread drops to zero by construction, immune to clock skew — with the server storing the newer of its `utc_now` and the conversation's newest message; and the sentinel remembers the newest message it already marked and never re-marks it, since an effect that can re-fire without progress is an infinite loop waiting for a trigger. Verified on the crashing scenario: exactly one mark-read POST, badge clears, no errors. |

## 3. State of the product so far

The DM write path is DB-hardened end to end: migration backfills the pair from `conversation_members`, and live negative tests confirmed each constraint fires (slug pair → uuid type error; valid members without membership rows → FK failure exactly at `COMMIT`; unordered pair, DM without pair, group with pair → the respective CHECKs). `data-model.md`/`shape-model.md` updated to match.

The two-tab demo works and was verified with two Playwright contexts: a Priya tab and a `?as=daniel` tab greet their own users, show different conversation lists and unread badges, a message sent from Daniel's tab lands in Priya's open DM in real time, and Daniel sees the announcement composer from his server-side manager permission with no flag. Transcripts open pinned to the newest messages at both viewports, follow incoming messages, and leave readers in history alone. Seed slugs for the demo: `priya` (default), managers `daniel`/`sofia`/`elena`, staff `amira`/`tomasz`/`marco`/`grace`/`liam`/`yuki`/`jamal`/`ines`/`stefan`/`hannah`/`omar`/`kasia`; browser tabs must go through Caddy (HTTP/2), not the vite port.

Suites after the session: `mix test` 32 (4 new: session bootstrap + `?as=` write authorship), `tsc`/`vitest` (17)/`vite build` clean.

**Next:** real auth (retiring `MockSession`, `/api/session`'s slug lookup, and the `can_post_announcements` override), notifications and onboarding from the roadmap, un-react, desktop layouts for `/people` & `/profile`, and the remaining static search fields.
