# Hotel Chat — Session 6 Summary: Backend Data Model + Live Shapes

**Date:** 2026-08-18 · **Format:** brief-driven autonomous implementation · **Brief:** `../../6-backend-data-model-ai-brief.md` · **Previous:** `session-5-summary.md`, `../agent_artifacts/data-model.md` / `../agent_artifacts/shape-model.md`

## 1. Premise

Session 5 had just finished the frontend work of setting up TanStack DB collections that use mock data — QueryCollections over table-shaped fixtures, with `collections.ts`'s header comment naming the swap contract for later. This session built the other half: real Ecto migrations + schemas for the full `data-model.md`, idempotent seed data reproducing the frontend's fixture dataset in Postgres, all 10 `shape-model.md` shapes implemented in the sync proxy, and — cashing in the contract — the frontend collections swapped from fixtures to live Electric sync.

## 2. Key decisions and forks in the road

| #   | Topic                          | Decision                                                                                                                                                                                                                                                                                                            |
| --- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Frontend/backend type mismatch | Cross-checked `schema.ts`/`fixtures.ts` against `data-model.md`: the frontend row types are narrower than their tables everywhere (missing `updated_at`, attachment metadata, soft-delete columns). Ruled not a backend concern — a shape's column list is allowed to select fewer columns than its table; migrations follow `data-model.md` in full regardless of what the mocks modeled. |
| 2   | Soft-delete columns never sync | `messages.deleted_at`/`deleted_by`/`deleted_kind` are on the table but excluded from every shape's column list. Deletion will be enforced by the shape's `WHERE deleted_at IS NULL`, not by shipping a tombstone flag for the client to filter on.                                                                |
| 3   | Client/server-generated UUID PKs | Every `id`-keyed Ecto schema uses `@primary_key {:id, :binary_id, autogenerate: false, read_after_writes: true}` — accepts a client-supplied id (needed for messages/reactions optimistic writes) while still reading back the DB's `gen_random_uuid()` default when omitted. Caught via a smoke test: without `read_after_writes: true`, `Repo.insert` silently returned `nil` ids. |
| 4   | Idempotent seed data            | `priv/repo/seeds.exs` reproduces the frontend's fixture dataset (cast, conversations, transcripts, reactions) using deterministic ids (sha256 of a stable slug, loaded as a UUID) and `on_conflict: :nothing` on every insert — safe to rerun. Wired to a new `mix db.seed` alias.                                |
| 5   | S8–S10 collapsed, not per-conversation | `shape-model.md` specifies `messages:{c}` as one shape per open conversation with a windowed subset snapshot. Implemented instead as one standing "all my conversations" shape each for `messages`/`reactions`/`attachments`, matching `collections.ts`'s own staged intermediate step; per-conversation windowing is still future work. |
| 6   | No auth yet → mock session      | `$me`/`$company` come from a new `HotelChat.Sync.MockSession`, computed with the same deterministic ids `seeds.exs` uses (extracted to `HotelChat.Seeds.Id`) — scoped to Priya @ Harbourlight. The frontend's `db/session.ts` and `db/presence.ts` moved from readable-slug placeholders (`'priya'`) to these same real UUIDs so both sides scope to identical rows. |
| 7   | Electric protocol gotcha        | A shape's `columns` list must include its table's primary key even if the client never uses it — `rosters` (S2b) omitting `id` per the doc's literal 3-column list 400s against real Electric. Fixed by adding `id` to both the shape definition and the `RosterEntry` type.                                     |
| 8   | Timestamp parsing                | Postgres `timestamp` (no tz) columns aren't auto-parsed by the Electric client (only `text`/`uuid`/`bool`/`int4`/`int8`/`jsonb` are) and arrive as `"2026-08-17 16:02:00"`. Every shape selecting one now passes a `parser` normalizing to real ISO-8601, keeping `derive.ts`'s string-comparison ordering correct. |
| 9   | `interface` → `type`             | `schema.ts`'s row types changed from `interface` to `type`: `electricCollectionOptions`'s generic constraint needs a type structurally satisfying an index signature, which `interface` declarations don't match even when every property is compatible.                                                          |

## 3. State of the product so far

Backend: 13 tables live via Ecto migrations (companies, locations, members, member_locations, member_settings, work_schedules, invites, conversations, conversation_members, messages, message_attachments, message_reactions, push_subscriptions), each with a matching schema module under `lib/hotel_chat/{companies,identity,conversations,notifications}/`. `mix db.seed` populates the same dataset the old frontend fixtures had — 1 company, 1 location, 16 members, 18 conversations, 89 conversation_members, 48 messages, 145 reactions.

`HotelChat.Sync.Shapes` now serves all 10 shapes from `shape-model.md` (was just a `group_chats` demo). `frontend/src/db/collections.ts`'s 11 collections all use `electricCollectionOptions` against `/api/sync/<shape>`; `fixtures.ts` is deleted — real data flows Postgres → Electric → Phoenix proxy → TanStack DB.

Verified end-to-end, not just type-checked: ran the real `@electric-sql/client` (`ShapeStream`/`Shape`) against the running dev proxy for all 10 shapes — row counts matched the seed exactly, timestamps parsed to correct ISO-8601, booleans/ints auto-parsed correctly. `tsc -b`, `vitest run` (17 tests), and `vite build` all pass. Not verified in an actual browser (no browser tooling available this session) — worth a manual look.

**Next session:** the roadmap's remaining data-model item — Create/Update API endpoints for writes (shapes only cover reads) — plus real auth to retire `HotelChat.Sync.MockSession`, and per-conversation windowed loading for S8 (decision 5) when message volume needs it.
